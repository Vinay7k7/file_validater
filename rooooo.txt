Architecture & Execution
Centralized Repository: Validation rules (YAML/README), Python validation scripts, and GitHub Actions workflow files are maintained directly in the Git repository.
Automated Trigger: A Pull Request containing SQL changes automatically triggers the GitHub Actions workflow.
Dynamic Validation: The workflow identifies the SQL entity type, such as CREATE, ALTER, DROP, or QUERY, and selects the appropriate validation logic.
Temporary Execution Environment: GitHub Actions provides a temporary Linux runner to execute the validation without requiring a dedicated server.
Validation: The Python validator loads the defined rules and validates the changed SQL file.
Reporting: The validation result is generated as a PASS/FAIL report and displayed within the GitHub Actions/PR workflow.
Merge Control: If validation fails, the workflow can fail the PR check and prevent the change from being merged until the issues are resolved.
